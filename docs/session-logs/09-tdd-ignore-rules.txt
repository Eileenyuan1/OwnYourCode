  commit first: the working tree was already clean after the last three commits.

  How parseGitHubUrl works now
  1. It tries new URL(url) and rejects the input if that throws. That covers the
     non-URL strings.
  2. It rejects anything that isn't https:.
  3. It rejects any host except github.com and www.github.com.
  4. It removes one trailing slash, splits the path, and requires exactly 2
     segments.
  5. It removes a .git suffix from the repo name.

  Every rejection returns the same message, Expected a URL like 
  https://github.com/{owner}/{repo}. The tests only need a non-empty message, so
  I didn't add a separate message for each case.

  Inputs this accepts that it probably shouldn't (no test covers them, so I left
  them out on purpose):
  - https://github.com/owner// passes with an empty repo name.
  - https://github.com//repo passes with an empty owner.
  - https://github.com/owner/.git passes with an empty repo after the suffix is
    removed.
  - Query strings and fragments are ignored, so
    https://github.com/owner/repo?tab=readme passes.

  If you want those rejected, the next step would be another small red test
  before refactoring.

  How shouldIgnorePath works (lib/rules/repo-import.ts)
  1. Split the path on /. The last part is the file name; the rest are folders.
  2. Ignore the file if any folder is in IGNORED_DIRS. Matching whole folder
     names is why src/build-utils.ts and .github/ are kept, and checking only
     folders means a file that happens to be named build isn't ignored.
  3. Ignore it if the file name is in LOCK_FILES.
  4. Otherwise, take the part after the last ., lowercase it so .PNG counts, and
     check it against IGNORED_EXTENSIONS. A file whose only dot is the first
     character, like .gitignore, is treated as having no extension and is kept.

  One way this goes past "minimum": the three sets hold the full lists from PRD
  §5.1, not just the extensions and lock files the tests use. A literal minimum
